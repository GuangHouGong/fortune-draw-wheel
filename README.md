# 土城廣厚宮功德會抽獎

手機、平板、桌機及現場投影使用的免費抽獎工具。採用 Vite、React、TypeScript 與 GitHub Pages，不需要後端、資料庫、帳號或付費語音 API。

- 線上網站：[土城廣厚宮功德會抽獎](https://guanghougong.github.io/fortune-draw-wheel/)
- Repository：`GuangHouGong/fortune-draw-wheel`
- 部署路徑：`/fortune-draw-wheel/`
- 活動資料保存在目前瀏覽器的 `localStorage`；換裝置時使用活動 JSON 備份。

## 從準備到抽完帶走

1. 建立活動：每場活動有自己的名單、分組、獎項及紀錄，可以複製或封存。
2. 準備名單：直接貼上、產生連號，或匯入 `.xlsx`、`.csv`、`.txt`。先預覽與選擇欄位，再決定新增或取代名單。
3. 設定獎項：安排名額、順序及限定組別，也可以不建立獎項，直接自由抽獎。
4. 抽獎前備份及試抽：下載完整活動 JSON；試抽不寫入正式紀錄。
5. 現場開獎：轉盤、跳號或直接揭曉；支援單抽、連抽及批次。主要按鈕在開始與停止間切換，連抽可暫停再接續。
6. 抽完帶走：保存名單 CSV、結果 CSV、這場活動或全部活動 JSON；缺席、放棄可保留紀錄並補抽原獎項名額。

頁面依活動、準備名單、現場抽獎、結果與備份、使用說明分開。使用 hash 路由，重新整理及 GitHub Pages 開啟連結不需要伺服器路由設定。

## 首頁與跨裝置操作

- 手機：標題使用完整寬度，吉祥物縮為輔助圖；建立活動與 JSON 備份匯入集中在同一區。活動主操作占整列，準備、結果等次要操作排在下方。
- 平板：歡迎文字與公仔並排，活動列表維持單欄，建立表單有充足輸入空間。
- 桌機：活動卡片分成兩欄，方便比較與接續多場活動；超長名稱可正常換行。
- 「查看我的活動」會移動焦點到列表，不更改活動網址。全部活動已封存時提供明確提示與查看入口；封存活動的主操作為查看結果。

## 台灣繁體中文文案

- 操作使用「儲存、匯入、下載、備份、重新整理」；加入名單、取代整份名單、補抽剩餘名額等提示直接說明動作與結果。
- 抽獎主操作與說明一致：「開始抽獎」「停止並開獎」「接續上次抽獎」。自動開獎約六秒；「再唸一次」使用裝置內建中文語音。
- 首頁以「活動備份」說明用途，下載及使用說明再標示 CSV／JSON 格式；不需先理解檔案格式就能找到操作。
- 用語參考台灣版官方介面的 [Microsoft 匯入與匯出](https://support.microsoft.com/zh-tw/outlook/import-and-export-outlook-email-contacts-and-calendar)、[Windows 備份與還原](https://support.microsoft.com/zh-tw/windows/experience/backup-recovery/back-up-and-restore-with-windows-backup)及 [Apple 朗讀說明](https://support.apple.com/zh-tw/guide/iphone/iph96b214f0/ios)。這是語系與易讀性調整，不代表使用者偏好的調查結果。
- 修改顯示文字時須保留 JSON 欄位、狀態值、儲存鍵與官方名稱。損壞資料的警告前綴與介面判斷需同步；相關既有測試同步驗證。

## 名單與檔案

建議名單維持 100 人內，最多 200 人。姓名中的空白會保留；建議一行一位或使用逗號分隔：

```text
王小明
李小華
John Smith
```

有編號及分組時，使用 Excel 或 CSV 的不同欄位，例如：

```csv
編號,姓名,組別
001,王小明,志工
002,李小華,會員
```

- Excel 讀取第一個工作表。優先辨識姓名、編號等常用欄位；找不到時使用第一個有資料的欄位，也可以在預覽手動選欄。
- 預覽會列出空白、重複及超過人數限制等問題。相同姓名可以用不同編號區分參加者。
- 舊版 `.xls` 請先另存為 `.xlsx` 或 CSV。
- 檔案只在瀏覽器讀取，不會上傳名單。
- CSV 以 UTF-8 BOM 輸出，時間使用 `Asia/Taipei`，並避免匯出文字被 Excel 當成公式。
- 完整 JSON 保存活動、名單、分組、獎項、抽獎設定、待公布結果、紀錄及顯示／聲音偏好。匯入備份會新增獨立活動，保留裝置上的既有活動。

## 抽獎規則與恢復

正式抽獎使用 `crypto.getRandomValues` 及拒絕取樣。按下開始時先抽出並保存本輪結果，畫面動畫只負責呈現結果；停止早晚不會重新選人。

重複中獎規則可選整場不重複、同一獎項不重複或允許重複。同一批次仍不會重複抽到同一參加者。連抽可逐位揭曉與暫停；正式待公布結果存在時，會限制修改該活動名單及獎項，重新整理後可接續本輪。

缺席或放棄會保留原紀錄、排除該參加者，並釋出原獎項名額。正式抽獎透過 Web Locks 協調同瀏覽器分頁，避免同場重複操作；沒有 Web Locks 的瀏覽器只能試抽，請改用新版 Safari 或 Chrome。

舊版瀏覽器資料會遷移到新版格式並保留舊鍵。資料無法解析時會顯示警告，不會直接覆寫損壞資料。

## 離線與版本更新

首次連網開啟後，請等畫面出現「已準備離線使用」。之後可以在同一瀏覽器離線重新開啟，使用抽獎、名單匯入及檔案匯出。Excel 解析程式即使尚未使用，也會與所有程式、圖像及圖示一起預先快取；沒有外部字型或語音服務依賴。

PWA 使用提示更新模式。有新版時會顯示「更新版本」；任何活動有待公布結果時會延後更新，包含暫停的連抽。套用更新前重新檢查並保存活動資料，完成本輪後才能操作更新。所有分頁關閉後，瀏覽器也可能自然啟用已下載的新版；未完成活動以版本化資料格式接續。

瀏覽器快取及本機資料不等於永久備份。清除網站資料、無痕模式、儲存空間不足或換瀏覽器都可能讓離線資料消失；正式活動前後請下載 JSON。離線狀態未準備完成時仍需先連網載入。

## 聲音、朗讀與大字

音效及自動朗讀預設關閉，可在現場設定啟用、試聽、再唸一次或停止朗讀。音效使用 Web Audio 在前端合成，不下載背景音樂，也不呼叫付費 API。

朗讀只使用裝置回報的本機中文語音（`localService`），優先繁體中文，可選語音與速度。長名單會分段完整排入語音佇列。裝置是否有中文語音、離線可用性及人名讀音由作業系統決定；沒有可用語音仍能完整操作與查看結果。首次播放需要實際點選操作，並確認裝置音量；通訊軟體內嵌瀏覽器不支援時，請在 Safari 或 Chrome 開啟。

大字模式將根字級由 18px 放大為 22px，開始／停止按鈕、獎項與中獎者文字一同放大；減少動畫與投影模式方便不同年齡使用。裝置不支援瀏覽器全螢幕時仍可使用頁面內的投影版面。

## 開發與驗證

建議 Node.js 24。PWA 使用 `vite-plugin-pwa` 2.0.0、Workbox 7.4.1；Vite base 固定 `/fortune-draw-wheel/`。每個預先快取檔案上限 5 MiB，超過時建置必須修正。

```bash
npm ci
npm run dev
npm run lint
npm test
npm run build
npm run preview
```

開發頁面通常為 `http://127.0.0.1:5173/fortune-draw-wheel/`。開發模式停用 PWA；離線驗證使用正式建置的 preview 或 HTTPS 網站。

最低驗收包含：

- 匯入欄位、姓名空白、同名不同編號、分組、人數 200 上限及獎項名額。
- 單抽、連抽、批次、重複規則、試抽不寫正式紀錄、重新整理接續及多分頁互斥。
- 首次連網載入但不先使用 Excel，完成快取後離線重開，第一次匯入 `.xlsx`、抽獎及下載備份。
- 版本更新出現時仍可完成待公布抽獎；完成後套用新版，確認活動與紀錄保存。
- 手機、平板、桌機尺寸、大字、200% 縮放、鍵盤焦點、減少動畫及投影版面。

**實機待驗收：** iPhone Safari、Android Chrome 的本機中文語音、聲音播放、離線重開、電話／切換 App 後接續，以及真實投影設備。桌機模擬尺寸不能取代上述實機驗收。

2026-10-05 改版驗證：44 項單元測試、lint、正式 build 與離線資源檢查通過。已在瀏覽器實測試抽不寫紀錄、手動停止、刷新恢復、跨分頁互斥、跳號連抽與暫停、批次開獎、缺席補抽、備份下載／重新匯入，以及待公布時禁止版本更新。停止 preview 伺服器後可重開，且未曾使用 Excel 的正式版分頁可首次離線匯入 `.xlsx`。已檢視 320／390px、820×1180、1180×820、桌機版面、大字與 Chrome 200% 放大；鍵盤「跳到主要內容」可正確移動焦點並保留活動網址。

## GitHub Pages 部署

`.github/workflows/deploy.yml` 在推送至 `main` 時使用 Node.js 24，依序執行 `npm ci`、lint、tests、build，再將 `dist` 發布至 GitHub Pages。

首次啟用 Pages 請設定 `Settings → Pages → Build and deployment → Source → GitHub Actions`。本地驗證、commit、push、Actions 部署成功、線上版本確認及實機驗收是不同階段，應分別記錄。
